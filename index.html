browser-agent

Find the bugs in the page
you are looking at.

Open your site in a real browser and it tells you what is actually broken: the buttons that do nothing, the images that never loaded, the errors only the browser can see. Then paste the list into Claude or Gemini and let it fix them.

Download it For CLI agents 
$ node browser.js open http://localhost:3000
$ node browser.js doctor

No install, no account. It uses the Chrome you already have.

The problem it solves

Claude, Gemini and ChatGPT write code they have never seen run. A button looks finished. An image path looks right. Nothing crashes. And you find out three days later, in front of a user.

Asking a web AI about it does not help, because it cannot see your page. So you end up describing the problem from memory, badly. This closes that gap: it looks, it writes the list, you paste it.

What it catches

One command, on the page you are already running.

  • ✓ Buttons that do nothing. It checks whether a click handler really exists, not whether the markup looks finished. Add --click and it presses the suspicious ones to prove it.
  • ✓ Images that failed to load, and links that lead to a 404.
  • ✓ JavaScript errors the page threw while it was open.
  • ✓ Text cut off with no sign there was more — the most common bug in generated layouts.
  • ✓ Fields with no label, and fields that get thrown away on submit.
  • ✓ Two elements sharing one id, and labels pointing at nothing.

How you use it

  1. Run doctor on the page you are working on.

  2. Read the list. Every finding is numbered, worst first, with the selector and the markup that caused it.

  3. Run doctor --paste --out=bugs.md and paste that file into Claude, Gemini or ChatGPT.

  4. They fix one at a time. Run doctor again to check.

$ node browser.js doctor --paste --out=bugs.md
OK wrote 3 findings to bugs.md   ← open it, copy it, paste it

It says this, not just "something is wrong"

So the AI receiving it does not have to guess.

#3  [high]  A button does nothing when clicked
      "Save changes"  ·  #save
      It is visible and enabled, and there is no click listener on it or on
      anything above it — nothing at all, so pressing it cannot do anything.
      Fix: Attach a click handler, or make it a real link.

For CLI agents

If you use Claude Code, Cursor or Codex in a terminal, the same tool gives your agent a browser it can drive with shell commands. No MCP server, no install — it is one file, and it talks to the Chrome already on your machine. 

$ node browser.js state        # what page is this?
$ node browser.js click "#save" # press something
$ node browser.js errors       # what went wrong?
$ node browser.js doctor       # find the bugs

Is this for you?

  • ✓ You have Node 22 or newer. That is the only requirement.
  • ✓ Chrome, Chromium or Edge is already installed. It finds it by itself.
  • ✓ You would rather not set up an MCP server just to look at a page.

Honest limits

Better you know now than later.

  • ✗ It finds problems, it does not fix them. That is what the AI is for.
  • ✗ It cannot see images. It reads the page as text, like you do.
  • ✗ You sign in yourself, through the real login form. It will not skip it for you.
  • ✗ --click presses real buttons. Anything that sounds destructive is skipped and reported instead.
